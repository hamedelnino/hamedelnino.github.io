Campus network redesign: 6 to 30 VLANs

Problem. About 20 critical server and switch alerts per month, with hubs and unstable links in the network.

What I did. Redesigned the network from 6 to 30 VLANs with a management VLAN and a separate Wi-Fi VLAN, default-deny access to servers and network devices, and SSH administration. Used Zabbix alerts to find and remove hubs and unstable links.

Result. Critical server and switch alerts fell from about 20 to fewer than 5 per month.

CiscoMikroTikVLANZabbix

Moodle holding up through exam periods

Result. Sustained about 1,500 peak concurrent users (3,000 registered).

MoodleRedisOPcacheNginx

Nextcloud compromised through a vulnerable app

Problem. CPU and memory hit 100% and Nextcloud went down.

Cause. Apache logs and the file system showed a compromise: malicious files in /tmp and /dev/shm and a malicious crontab entry, brought in through a vulnerable app.

What I did. Removed the malware, the crontab entry and the app, and blocked the IPs the malware used. Tightened firewall rules, reissued certificates and passwords, and moved the server behind ArvanCloud so it only accepts traffic from ArvanCloud’s IP addresses.

ApacheIncident responseHardening

Switching loop traced from MAC flapping

Problem. Switch logs reported MAC flapping and a loop on the network.

Cause. A faulty cable and a user’s device.

What I did. Followed the flapping MAC addresses from switch to switch to the exact port and corrected the cause. Then enabled BPDU Guard and storm control so a repeat is stopped at the port.

CiscoSTPBPDU GuardStorm control

Veeam jobs failing with certificate errors

Problem. On about 30 jobs and 20 TB of data, every job failed with certificate errors, and repositories also ran out of space.

Cause. The servers’ clocks were out of sync.

What I did. Fixed time synchronization with NTP, after which the jobs ran again. Then tuned retention so the repositories stopped filling up.

Veeam v12NTPRetention

Physical Windows server moved to a VM

What I did. Backed it up with Veeam Agent, restored it with Instant Recovery on ESXi, then took a full backup of the new VM.

Veeam AgentInstant RecoveryESXi

Zabbix monitoring beyond the default templates

Problem. Standard templates cover the basics, but GPU health, TLS certificates and security events weren’t visible.

What I did. Run Zabbix 7 across 100+ servers, 45 network devices and 1,000+ metrics, using both the Zabbix agent and SNMP. Built the GPU monitoring with AI assistance and a lot of trial and error (a script around nvidia-smi exposed as UserParameters, with a template and triggers for temperature, memory and missing data). Set up Zabbix’s official Agent 2 certificate template with per-site macros, tracking each certificate’s expiry date and fingerprint, with an alert one week before expiry, which caught the last two approaching expirations before they caused outages. Only high-severity triggers go to email and SMS. Also built SNMP discovery for Cisco and MikroTik, plus maps and dashboards.

Zabbix 7SNMPAgent2Certificates

Veeam job monitoring in Zabbix

What I did. Adapted a public example into a PowerShell script (with AI assistance and a lot of trial and error) that runs on the Veeam server under a least-privilege local account (no password stored) and sends each job’s result, duration and age to Zabbix with zabbix_sender and low-level discovery. The template alerts on failed or warning jobs, jobs that are too old or run too long, and a silent monitoring script. The script runs in production; the updated template is published for testing.
